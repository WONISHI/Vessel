# 第一轮常驻内存优化验证

日期：2026-11-04。平台：macOS arm64，Electron 39.8.10。

## 已实现

- 每个工作区内可安全淘汰的文档实例采用 LRU，上限为当前文档加最近两个后台文档。标签页继续保留。
- 离开工作区或停留工作台 30 秒后，释放这些后台文档实例。工作区目录与标签数据保留。
- Markdown、代码文档重开时等待未完成的写入；失败的写入保留草稿并显示恢复状态。
- Markdown 卸载前补写尚未触发延迟 input 回调的内容，保存文本偏移形式的选区与滚动位置，不持有旧 DOM Range。
- Monaco 记录视图状态，清理焦点订阅，在最后一个共享编辑器释放后销毁 model，保护拆分视图。
- Office 标签数据保留，非活动 PDF 预览卸载；整个 Office 页隐藏 30 秒后释放 PDF 预览。

安全边界：浏览器网页、白板/思维导图等未接入状态恢复的类型不强制淘汰；可编辑 Office 文档继续保活，避免丢失运行时中的修改、撤销记录或阅读位置。

淘汰会重建编辑器，冷切换可能略慢；重建后不承诺恢复完整撤销历史。本轮没有调整同步策略、自动保存合并或启动拆包。

## 对比方法

使用隔离 Electron 测试窗口，实际挂载本项目的 MarkdownCanvas 与 Vditor。每轮依次打开 12 个不同路径的 Markdown 标签，每份文档包含 1000 个标题和 1000 个正文段落。读取与保存接口使用相同的测试数据桩，不接触真实文档，不测试网络和磁盘性能。

基线使用修改前的 DocumentTabs；优化组使用本轮的有界缓存。为隔离文档缓存收益，两组共用相同的当前 Markdown 渲染实现，未使用的导航、白板与 Monaco 模块做相同替身处理。因此这些数值不是完整 Vessel 应用的内存总量，也不是与用户此前 648 MB 截图的直接对比。

顺序为：基线 → 优化 → 优化 → 基线，每次销毁窗口并创建新的渲染进程。最后一份文档准备完成后空闲 1.5 秒采集自然内存；随后两组均通过 HeapProfiler.collectGarbage 显式触发 GC，再采样。

统计采用 app.getAppMetrics 中对应渲染进程的 workingSetSize；单位为 MiB（1024² 字节）。JS 堆来自启用精确内存统计的 performance.memory。没有将 GPU、主进程或网络服务计入下表。

## 结果

| 指标，两轮平均 | 基线 | 优化后 | 下降 |
| --- | ---: | ---: | ---: |
| 自然采样，渲染进程 working set | 1230.81 MiB | 834.27 MiB | 396.54 MiB，32.22% |
| 统一 GC 后，渲染进程 working set | 923.69 MiB | 476.35 MiB | 447.34 MiB，48.43% |
| 统一 GC 后，JS 堆 | 248.35 MiB | 77.83 MiB | 约 68.66% |
| 活跃挂载编辑器数 | 12 | 3 | 75% |
| DOM 元素数 | 183719 | 47099 | 约 74.36% |

原始数据见 phase1-memory-results.json。working set 会随垃圾回收与系统回收时机波动，本测试只有两轮配对样本。自然采样下降约 32% 是本测试场景的结果，不代表任意文档数量、Office 或浏览器工作负载都下降相同比例。

## 功能验证

定向测试覆盖：LRU 淘汰与重开、后台超时释放、Office 编辑实例保护、PDF 预览卸载与恢复、在途保存等待、保存失败草稿恢复、Markdown 选区/滚动恢复、延迟 input 前卸载补写，拆分代码编辑器共享 model 的释放时机，以及初始化完成晚于淘汰时的全局注册清理。前端类型检查通过。

用户实际场景仍需安装新版后，在相同文件、相同标签访问顺序、相同空闲时间下比较性能页的进程内存；不能由此报告推算原来 648 MB 必然下降至某个固定值。
