# 进程诊断与后台资源释放

日期：2026-11-04。

## 已修复的保留路径

1. 浏览器设备列表此前创建并长期持有隐藏 DevTools WebContentsView。现在只缓存提取后的普通设备数据；读取成功、失败或超时都关闭临时 WebContents。用户实际打开的网页控制台不会因此被关闭。
2. TypeScript 代码检查 worker 此前永久存活。现在无任务 60 秒后终止，下次检查时重建。同一路径尚未执行的旧内容被最新内容替代，待执行队列最多 8 个文件、估计文本量最多 16 MiB，避免不断向 worker 投递完整源码。正在执行的检查不会被中断。
3. 浏览器活动页可见性现在同时考虑整个浏览器功能是否在前台，隐藏时不再触发前台主题处理。取消未访问浏览器模块的自动预热。
4. 独立预览入口不再静态初始化完整工作区路由。已检查独立预览窗口：关闭时会清空主进程预览状态；文件切换只挂载当前预览，无需强制销毁尚在使用的窗口。

可编辑 Office、浏览器网页及其未保存状态仍受保护；本次没有通过强制杀进程或自动丢弃表单来制造内存下降。此前工作区文档缓存及 Office PDF 预览释放策略继续保留。

## 新增诊断信息

- 使用 app.getAppMetrics 的操作系统 PID，与 WebContents、mainFrame.framesInSubtree 中的 frame.osProcessId 对齐；不使用 Chromium 内部 processId 冒充 OS PID。
- 每个渲染进程列出页面/frame 来源、标题、所属窗口、地址和标识；Office iframe 补充文档名称，便于区分同一进程中的多个文档。一个进程可以对应多个来源，不能给每个 frame 重复分摊进程内存。每个进程最多返回 50 条来源。
- 页面地址删除用户名、密码、查询参数和非路由 fragment；文件地址只保留文件名及路由。诊断仍含本地页面标题，不会自动上传。
- 内存排序、采样变化及峰值；最多 120 个轻量历史采样点，避免监控本身无限积累数据。
- 主进程 RSS、主线程 JS 堆、主线程外部内存和 ArrayBuffer、事件循环忙碌率，以及 TypeScript worker 的状态、队列、最近堆采样和预计释放时间。
- 当前渲染进程的浏览器 JS 堆估计、DOM 数量、编辑器/隐藏文档/iframe/webview 数量，以及本次监控期间的长任务计数。
- “复制诊断”导出当前快照、资源统计及有限历史，便于对照真实工作负载。

RSS 包含 worker 所在进程的内存；主线程 heapUsed 不包含 worker 的堆。ArrayBuffer 是外部内存子集，以上数值不能简单相加。宿主窗口可见不表示其中的子页面在前台；无法确定的子页面可见性显示“未确认”。

## 验证

- 13 个定向测试文件、21 项测试通过，覆盖 OS PID 映射、脱敏、进程生命周期变化、设备列表提取后的关闭与缓存、worker 合并与空闲退出、旧 worker 退出事件隔离、轮询清理、诊断复制、独立预览及后台网页行为。
- 主进程和前端类型检查通过，生产构建通过。另验证了独立预览无工作区路由时的链接渲染及 Vditor 初始化/淘汰，共覆盖 28 项不同的定向测试。
- 使用真实代码检查 worker、Node 20.20.0 和临时 TypeScript 测试文件执行检查，确认真实诊断错误仍能返回；60 秒空闲后 worker 已终止。原始数据见 diagnostics-worker-release.json。
- 该隔离 Node 测试进程 RSS：检查前约 34.5 MiB，检查完成后约 183.4 MiB，空闲释放后约 58.8 MiB。它证明 worker 释放路径有效，不能作为完整 Vessel 1.4 GiB 占用的对比结果。
- 新诊断页使用明确标注的测试数据做了浅色、深色渲染与复制操作验证；页面示例中的旧 PID/内存不是对用户现有进程的实时归因。

安装新版并完全退出旧版本后，应在实际工作负载下观察来源列表和趋势。旧截图中的两个额外渲染进程无法仅凭 PID 追溯身份；需要新版实时来源数据确认，不能预先断言它们就是 Office 或隐藏 DevTools。
