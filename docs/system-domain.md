# 系统域本机连接配置

系统域在主进程启动时读取 PostgreSQL 连接，不经过渲染进程，也不把数据库密码写进源码或安装包。

优先级：

1. 主进程环境变量 `VESSEL_SYSTEM_DATABASE_URL`。
2. 开发环境：项目根目录 `.vessel-system-domain.local`。
3. 已安装应用：Electron `userData` 目录下的 `.vessel-system-domain.local`。

配置文件只包含一行完整 PostgreSQL URL，权限应为 `0600`。该文件是本机明文秘密配置，不是加密保险库；不要提交、同步或分发。修改后需重启主进程。

连接地址必须声明 `sslmode=require` 或 `sslmode=verify-full`；实际连接统一校验证书，并启用 PostgreSQL SCRAM 通道绑定。Neon 控制台提供的连接池地址可用于此配置。

没有配置时继续使用本地数据。打开登录页后，系统域使用本机配置连接数据库，注册或登录的是 Vessel 账号；登录成功切换远程数据，退出登录恢复本地数据。

首次登录空账号时，Sonner 会询问是否同步本机业务数据库。明确同意后才将本机数据写入该账号的远程业务表；不同意则只创建空表。选择成功后记录初始化标记，避免空账号每次登录重复询问；已有远程数据的账号不会提示。写入使用事务并再次检查账号是否为空，避免覆盖其他设备刚写入的数据。密码保险库继续通过单独的授权导入流程迁移。

## 发布限制

这仅用于开发者本机或受信任的私有部署。配置文件不会随安装包发布，所以其他安装设备不会自动拥有系统域连接。

公开的多用户系统域需要独立后端接口：后端保管 Neon 凭据并执行认证与逐用户授权，桌面客户端仅持有用户会话。不能把 `neondb_owner` 或其他共享数据库凭据嵌入桌面发行版；现有客户端中的账号过滤不能替代服务端授权。

若连接凭据出现在聊天、截图或日志中，应在 Neon 重置对应角色的密码，再更新本机配置并重启。仅轮换数据库角色密码不改变 Vessel 登录密码或保险库解密密码。
